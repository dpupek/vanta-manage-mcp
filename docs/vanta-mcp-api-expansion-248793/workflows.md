# Workflows and user stories

Epic: [248793](https://darwin-global.fogbugz.com/f/cases/248793/). All story labels below are planning labels; child cases have not been created. Acceptance maps to the [iteration plan](download-integrity-and-api-refresh-plan.md).

| Workflow / story                                   | Persona and motivation                             | Steps                                                                                                                                                                                                                                             | Acceptance / linked work                                                                                                                                                              |
| -------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| W1 / S1: Retrieve an attachment                    | Compliance analyst needs a usable source file      | Read document/uploads or Trust Center resource; select the exact object/version; request an explicit destination; fetch raw bytes; save and hash; return receipt; optionally preview separately                                                   | PDF/XLSX/PNG/JPEG bytes match fixtures through registered MCP dispatch; phase 1; epic 248793, child case: no case yet                                                                 |
| W2 / S2: Verify a published artifact               | Evidence publisher needs defensible identity       | Capture source and actual uploaded-artifact hash; retrieve the selected representation; compare expected hash; distinguish transfer completion from original identity; retain receipt                                                             | Equal hashes establish identity; missing baseline yields unknown; differing hashes yield mismatch without silently converting; phase 1; epic 248793, child case: no case yet          |
| W3 / S3: Retrieve approved policy content          | Policy reviewer needs the approved version         | Read policy/version metadata; classify identifiers; discover a documented artifact route; fetch if supported; otherwise return the unresolved identity and authenticated-browser/manual handoff; hash any supplied file and record its provenance | Policy artifact IDs never become evidence document IDs by assumption; fallback clearly records what was actually obtained; phase 2; epic 248793, child case: no case yet              |
| W4 / S4: Adopt current API contracts               | Developer needs stable tools with current inputs   | Download three official specs; diff identities and schemas; classify changes; pin exact bytes; regenerate; preserve names; exercise changed HTTP contracts; publish help                                                                          | Every published identity has one tool; all baseline names retain identities; binary media handling survives regeneration; phase 3; epic 248793, child case: no case yet               |
| W5 / S5: Review vendor exposure                    | Security operator needs actionable vendor context  | Select vendor; independently paginate assessments, external findings, alerts and incident alerts; review category/engagement relationships; prepare explicit actions; confirm writes and read back                                                | Partial inventories are labeled; unrelated data preserved; bulk per-item failures exposed; phase 4; epic 248793, child case: no case yet                                              |
| W6 / S6: Connect risk and issues                   | Risk owner needs traceable relationships           | Read risk and mapped accounts/assets/integrations/issues; inspect issue filters/details and enterprise-risk links; propose add/remove changes; confirm; reread affected mappings                                                                  | No inferred causal relationships, no guessed replacement semantics, no enterprise-risk write inferred from a read endpoint; phase 5; epic 248793, child case: no case yet             |
| W7 / S7: Evaluate evidence and maintain frameworks | Program admin needs evaluation context and exports | Retrieve/hash evidence; explicitly request document evaluation; poll documented status within bounds; read findings; export a framework and retrieve its result; review lifecycle/variant action; confirm writes                                  | Evaluation does not declare compliance; export transport inspected before routing to downloader; timeout never silently restarts a job; phase 6; epic 248793, child case: no case yet |
| W8 / S8: Maintain personnel requirements           | Personnel admin needs consistent obligations       | Read requirement sets/custom requirements/group associations; review desired detail and requirement edits; show affected scope; confirm update; read back; handle group deletion separately                                                       | PATCH/replace semantics verified; deletion impact shown; feature denial preserved as an API error; phase 7; epic 248793, child case: no case yet                                      |
| W9 / S9: Accept and adopt a release                | Maintainer needs a verifiable installed runtime    | Complete local gates; collect scoped live receipts; report untested surfaces; release when authorized; restart/update MCP; inspect capabilities version/SHA; smoke-download fixtures through installed tools                                      | Installed runtime identified; file receipts match; readback guard retained; open acceptance stays visible; phase 8; epic 248793, child case: no case yet                              |

Each story's concrete checkbox tasks, decisions, dependencies, and validation gate are in its corresponding phase. Reuse current vendor/issue workflows and generated dispatch; add a new workflow only when these steps cannot be expressed clearly through those surfaces.
